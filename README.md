# SBL shared-site refactor

This folder contains the current SBL pages with a non-destructive shared site shell.

## Shared files

- `js/sbl-site.js` — single source of truth for site navigation and shared nav behavior.
- `js/sbl-themes.js` — existing single source of truth for theme presets.
- `css/sbl-site.css` — shared navigation/shell styling.

## Navigation

Edit `NAV_ITEMS` in `js/sbl-site.js` to add, remove, reorder, or rename navigation buttons.

The `file` value is the actual HTML filename. The `label` is the page name shown to users.

## Safety

Page-specific JavaScript was intentionally left in the individual HTML files. This refactor does not attempt to rewrite the application's roster, trade, free-agency, stats, or analysis logic.


## Phase 2 — shared data foundation

Added:
- `js/sbl-supabase.js` — single shared Supabase client.
- `js/auth.js` — shared session/profile/commissioner helpers.
- `js/services/rosters.js` — shared reader for the existing `__rosters__` record.

These are compatibility-first services. Existing page-specific queries were not
deleted or rewritten. The next migration can move one page at a time onto these
services after verifying behavior.


## Phase 3B — shared Pokémon + sprite service

Added:
- `js/services/pokemon.js` — shared Pokémon normalization and universal Showdown sprite handling.
- All pages now load the shared Pokémon service.
- Existing page-specific sprite renderers are left intact for compatibility; the shared service catches failed sprite loads and retries aliases and multiple Showdown sprite generations.
- Known spelling/form issues including `Chiyu` → `Chi-Yu` and `Scovillain`/similar variants → `Scovillain` are handled centrally.
- The duplicated inline `sitewide-sprite-fix` blocks were removed from individual pages.

No database schema or roster/trade/replay behavior was changed.


## Phase 4F.3 — Local Sprite Engine

Pokémon sprites now use deterministic Gen 9 Scarlet/Violet front-sprite URLs generated by `js/pokemon-dex-ids.js` + `js/services/pokemon.js`, delivered through jsDelivr from the PokeAPI sprites repository. There is no fallback waterfall, MutationObserver, local sheet, or custom sprite cache. The same renderer is used by normal cards and dynamically generated popups. See `PHASE-4F3.md` and `SPRITE-CREDITS.md`.


### Sprite naming rule (Phase 4F.5)
Showdown HOME uses compact filenames for several species whose human names contain hyphens (for example `chiyu`, `tapukoko`, `greattusk`, `ironvaliant`, `mrmime`, `porygonz`) but preserves hyphens for actual form suffixes such as `deoxys-attack`. Do not globally strip or preserve hyphens; use `SBL.pokemon.spriteFilename()`. `Scovillalian`, `Scovillain`, and `Scovillain` are canonicalised to `Scovillain`.
